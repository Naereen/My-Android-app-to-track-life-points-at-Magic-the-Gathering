## Repository Overview

**Naereen's MTG Life Counter** is a web-based life point tracker for _Magic: The Gathering_, built with:

- **SvelteKit** (web framework)
- **Svelte 4** (UI components)
- **TypeScript** (type safety)
- **Tailwind CSS** (utility-first styling)
- **Vite** (build tool / dev server)
- **Vitest** (unit testing)
- **Capacitor** (Android APK packaging via `@capacitor/android`)

The app is deployed as a static site to GitHub Pages and also packaged as an Android `.apk`.

## Development Commands

All commands should be run from the **repository root**.

```bash
# Install dependencies
npm install

# Start development server (hot-reload at http://localhost:5173)
npm run dev

# Type-check with svelte-check
npm run check

# Type-check in watch mode
npm run check:watch

# Run unit tests (Vitest)
npm run test

# Lint (Prettier + ESLint)
npm run lint

# Auto-format code (Prettier)
npm run format

# Build for production (output: build/)
npm run build

# Preview production build locally
npm run preview
```

> **Always run `npm run lint` and `npm run check` after making changes** to ensure formatting and type correctness.

## Testing

Tests use **Vitest**. The test file entry point is `src/index.test.ts`. Run all tests with:

```bash
npm run test
```

When adding new functionality, add corresponding tests in a `*.test.ts` file alongside the source file or in `src/`.

## Code Style & Conventions

- **Formatting**: Prettier is configured via `.prettierrc`. Always run `npm run format` before committing.
- **Linting**: ESLint with `eslint-plugin-svelte` and `typescript-eslint`. Run `npm run lint` to check.
- **TypeScript**: Strict mode is enabled. Avoid `any`; add proper types for all new code.
- **Svelte components**: Place reusable components in `src/lib/components/`. Use sub-folders (`player/`, `modals/`, `menu/`, `shared/`) to group related components.
- **State management**: Use Svelte stores in `src/lib/store/`. Keep stores focused on a single concern. The `persist.ts` helper provides LocalStorage persistence.
- **i18n**: All user-visible strings should go through `svelte-i18n`. Add translations to `src/locales/`.
- **CSS**: Prefer Tailwind utility classes over custom CSS. Global styles go in `src/app.css`.
- **No hardcoded player counts or life totals**: These are driven by `appSettings.ts`.

## Android / Capacitor

The app is packaged for Android using **Capacitor 8**. The Android project lives in the `android/` directory (not committed; generated by `npx cap sync`).

Key commands (require Android SDK / Android Studio):

```bash
# Sync web build into Android project
npx cap sync

# Open in Android Studio
npx cap open android

# Run on connected device/emulator
npx cap run android
```

The APK is built and signed via GitHub Actions (`.github/workflows/android_build.yml`) on every release tag.

---

## CI / GitHub Actions

| Workflow            | Trigger        | What it does                                   |
| ------------------- | -------------- | ---------------------------------------------- |
| `deploy.yml`        | Push to `main` | Builds static site and deploys to GitHub Pages |
| `android_build.yml` | Release tag    | Builds and signs the Android APK               |

Both workflows use `ubuntu-latest` and Node.js 18+.

## What to Avoid

- Do **not** commit secrets, keystore passwords, or credentials (the `Makefile` references `~/naereen.jks`; keep it out of source).
- Do **not** remove or skip existing tests.
- Do **not** add new npm dependencies without a clear reason; prefer solutions using existing libraries.
- Do **not** modify generated files in `build/` or `.svelte-kit/` — these are gitignored and regenerated.
- Do **not** hard-code user-facing strings; use `svelte-i18n` instead.
